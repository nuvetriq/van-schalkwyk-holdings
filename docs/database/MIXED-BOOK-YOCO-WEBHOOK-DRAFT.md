## Confirmed Yoco Checkout API protocol

- One checkout is created on the server via `POST https://payments.yoco.com/api/checkouts`, using **integer ZAR cents**, a server secret key and an idempotency key. The customer is redirected to Yoco's `redirectUrl`. A browser `successUrl` return is NOT proof of payment.
- Register a Yoco Checkout API webhook; `whsec_` signing secret must be kept in Netlify environment variables and never shown in source or screenshots.
- HMAC-SHA256 signature calculation: concatenate `webhook-id.webhook-timestamp.<exact unmodified request body>`; decode the base64 suffix of the `whsec_` secret; compare with `v1,<base64>` entries in the `webhook-signature` header in constant time.
- Reject timestamps more than 180 seconds old/new. Yoco retries callbacks after transient failures; database event IDs and payment IDs must be idempotent.
- Only `payment.succeeded` with the correct payment status, exact stored integer ZAR amount, processing mode, order/checkout association and unique payment reference can mark an order paid. Signed failures/refunds never dispatch PDF delivery.
- A checkout ID is generated by Yoco when the checkout is created; the merchant can't know it at the time the initial checkout metadata is sent. A signed `metadata.orderId` *alone* is not proof that a given payment belongs to a particular stored Yoco checkout. If the signed event does not supply an authenticated checkout ID, independently reconcile against Yoco's own records/API before calling the paid-order ledger. Do NOT simply copy `storedOrder.checkout_id` into the verified event and call it confirmation.
- The webhook response must be timely. After a transient stored-checkout mapping race or temporary database error, return a retryable HTTP status; do not falsely acknowledge an unprocessed payment. Distinguish unrelated merchant checkouts from our order events without disclosing private data.

## What this branch implements now

`netlify/lib/mixed-book-yoco-webhook-verify.mjs` is a **pure server-only verifier** and conservative reconciliation helper. It has no Netlify Function default export, no HTTP endpoint, and cannot receive webhooks from Yoco yet. The module:
- Rejects invalid raw-body signatures, forged/expired timestamps, oversized bodies, malformed secret/signature, malformed orders, wrong amount/currency/mode, and conflicting checkout fields.
- Returns structured `payment.succeeded` details only after the signature validates, without inserting a paid order or sending an email.
- When signed event has no checkout ID, returns `independent-checkout-reconciliation-required`, not a settlement authorization.
- The repository's real PostgreSQL tests cover atomic paid-order+suborder+outbox storage, separate from the new signature tests.
